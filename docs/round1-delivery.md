# 第一轮交付：安卓规范巡查基础

本轮把现有截图分析扩展为可绑定规范、保存版本和证据的巡查流程。沿用 FastAPI、PostgreSQL、Worker 和 React，不引入额外服务。

## 使用方式

1. 打开「Skill 编辑 → 截图分析 Skill」，新建 Skill，类型选择「规范巡查」。
2. 填写规范名称、版本、来源和原文。选择该类型后，「上传 Markdown」可载入 `.md` / `.txt` 原文。
3. 为每条检查填写唯一编号、条款位置和判定标准。检查项由使用者确认，文档不会自动变成可执行判据。
4. 在任务中绑定该 Skill。任务运行创建时保存完整定义快照；运行过程中修改 Skill 或解绑不会改变该次运行的规范。
5. 在任务结果中查看逐项结论、实际观察和证据区域。截图详情可切换不同 Skill 及历史分析版本，展开当时的规范原文和模型调用记录。
6. 可导出 JSON、Excel 或 ZIP。Excel 的长字段按 `字段名__part_00001` 等列分片，按编号连接可恢复完整原文或 JSON；文本单元格不会作为公式执行。

已有普通分析、持续观察、新品楼层和二级 Tab 报告继续保留。新品专用报告同时提供统一的检查结果视图；未记录的原规范文字保持缺失，不补造历史版本。

## 结果与追溯

- 执行状态与规范结论分开：分析成功可以包含不符合或待确认项。
- 结论为 `pass`、`fail`、`uncertain`、`not_applicable`。缺少检查项、有效证据区域或判定依据时，不能保存为通过。
- 模型输出证据使用 0–1000 归一化坐标，后端换算为原图像素，避免图片缩放导致标注偏移。
- 每条分析保存 Skill 定义、规范原文/版本、定义 SHA-256、目标页判断和模型调用记录。重新分析前归档旧结果，失败时清除当前旧结论与旧向量。
- 记录请求模型、接口返回模型、服务端点主机、调用用途、耗时和失败类型。返回模型名是接口报告的标识，不能独立证明服务内部的模型权重。
- AutoGLM 手机导航记录流式请求；新品、二级 Tab、促销检测及普通视觉分析记录后端调用。规则控制手机时没有 AutoGLM 导航请求。
- 调用记录不保存 API key、请求图片、Prompt 或异常正文。文件损坏会明确记为 `trace_error`；记录故障不会掩盖模型错误或阻止任务释放设备。
- 自定义及系统 Skill 的输出 Schema 在执行时校验，外部 Schema 引用被拒绝。

## 验证记录

测试在独立 Git worktree、临时 Python 环境和临时 PostgreSQL/pgvector 数据库中执行，未使用业务数据库进行测试。覆盖目标页布尔值误判、模型 fallback、请求间记录隔离、规范复用、运行快照、失败重分析、历史权限、Schema 校验、证据坐标及长文档导出。

- 后端与 Worker 联合回归：229 项测试及 14 项子测试通过。
- 按后端依赖独立安装的环境：207 项后端测试及 14 项子测试通过。
- 两组环境均有 8 条既有依赖弃用警告，无测试失败。代码与导出边界复核未发现剩余新增问题。

前端 TypeScript/Vite 构建通过。Ego Lite 在临时数据库的预览环境中验证规范编辑与版本保存、结果展示、历史选择和证据区域显示。

真实视觉接口回放使用 [双入口排列试用规则](specifications/dual-entry-inspection.json)，从项目现有 3.7 检查抽取：

| 场景 | 历史截图 | 结论 | 证据 |
| --- | --- | --- | --- |
| 新品频道首屏 | 9 月 1 日任务 `db2f25b9…` 原图 | 符合 | 右侧「尖货抽签」「10点抢新」上下排列 |
| 新品频道中的促销贴片页面 | 任务 `88a4babe…` 静态帧 | 符合 | 同一双入口区域上下排列 |

这两个场景仍属于京东新品频道，验证的是跨场景复用和证据链。截图中的双入口及标注位置已人工核对；试用规则尚需业务规范负责人校准。完整回放结果位于本机 `data/tasks/round1-validation/inspection-replay.json`（生成产物不纳入 Git）。本次接口请求 `GPT-5.5`，返回标识 `gpt-5.5-2026-04-24`；四次视觉调用均成功。

可对其他已有截图复用同一脚本，无需操作手机或写入数据库：

```sh
python scripts/replay_inspection.py \
  --spec docs/specifications/dual-entry-inspection.json \
  --capture '场景一' /path/to/first.png \
  --capture '场景二' /path/to/second.png \
  --output /path/to/replay.json
```

## 上线与后续验证

后端新增 `jsonschema` 依赖；启动时通过现有 `ensure_schema()` 增加规范、追溯、运行快照字段及 `analysis_revisions` 表。旧记录的快照字段保持空值；旧运行重分析会明确标记使用分析时的当前 Skill。

当前未连接安卓设备，新增能力的真机端到端巡查待验证。第一轮保持单手机执行；多手机调度、iPhone、PDF/Word 自动解析及规范自动拆解不在本轮交付内。向量化沿用现有异步流程，并发重新分析的旧向量回写问题留待后续处理。
