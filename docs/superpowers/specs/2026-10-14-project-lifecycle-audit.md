# 全程：以项目为上下文的对话式走查

日期：2026-10-14  
状态：第二版界面规划与交互 Demo。此方案替代此前的看板、版本页和问题中心方案；正式后端尚未改造。

## 产品入口

用户只需要理解三个动作：**发材料、看结果、继续复查**。

参考 ChatGPT 的实际界面，采用白色主区、浅灰侧栏、居中输入框、连续对话、按需展开的内容。参考的是输入与阅读方式，不复制无关的模型切换、语音或多应用导航。

- **首页**：一个输入框，可发项目名称、链接、HTML、手机截图和规范；两个示例帮助首次使用。
- **左侧**：新建项目走查、搜索项目、我的项目。点击项目继续，不另建任务管理页面。
- **项目内**：顶部持续显示项目名，下面是一条走查记录流；底部输入框始终用于补充材料与提问。
- **结果**：先说需要改什么；每项点击展开“发现、依据、建议”。下一步直接在结果下方操作。

## 同一个项目如何贯穿上线前后

**项目是归属，对话是操作入口，每次审核是独立记录。** 同一个会话窗口不等于已经核实同一个业务对象；正式关联依靠固定 ID。

```text
11.11 官方会场（固定项目 ID）
  ├─ 上线前走查 → 修改稿复查 → 补证复核 → 审核人确认
  │                                      ↓ 保存为基线
  └─ 上线后手机走查 ← 引用这份已确认的基线
          └─ 继续整改、补充证据和复查
```

每份结果保存自己的 `projectId` 和结果 ID。审核人确认一份证据完整的上线前结果后，项目保存 `approvedPreReportId`。后续手机走查保存自己的结果 ID，同时将当时的上线前记录写入 `baselineReportId`。旧手机结果不因为后来换了基线而改变引用。

界面只露出必要信息：

1. 项目名一直可见，提醒用户材料会归到哪里。
2. 每轮标记“上线前 · HTML”或“上线后 · 手机端”。
3. 手机结果显示“已关联本项目上线前记录”，点击可返回原依据。
4. 没有已确认基线时，明确显示“本轮为独立检查”，不声称完成发布一致性验证。

正式接入必须进一步核对会场/页面业务 ID、发布修订、规范适用范围和证据哈希。名称相同、同一 URL 或处于同一对话都不能替代这些核实。多次发布的版本信息保存在记录详情中；需要选择时才在会话里询问，不在首屏放版本管理器。

## 用户实际怎么用

| 用户动作 | 系统在当前项目中完成的事 |
| --- | --- |
| “审核这个会场的上线前 HTML”并提供材料 | 登记项目与审核对象，沿用已确认规范，生成一轮上线前记录 |
| 展开一条问题 | 就地查看发现、依据、证据与修改建议 |
| “我改好了，再看看”并提供新稿 | 追加复查结果，保留原始问题；缺证项继续待确认 |
| 点击“确认本轮审核” | 保存审核人确认和这轮基线，不执行部署 |
| “已经上线，看看手机端”并提供截图 | 归入同一个项目，关联确认过的上线前基线，核对线上效果 |
| 从左侧重新进入项目 | 接着此前的上下文补证和复查，不重复配置对象与规范 |

信息不足时只补问当前需要的内容。例如没有材料就问链接或截图；无法确认对象映射就先核实对象；规范不明确就先选择或确认规范。不会因用户说“改好了”就直接关闭问题，也不会从静态截图推断跳转已经通过。

“复查修改稿”用于重新提供材料；“检查上线效果”用于继续同一项目，不是新建另一个项目。只有“新建项目走查”才创建新的项目归属。

## 复用当前项目的实现方式

继续复用 `Task / TaskRun`、Skill 规范快照、H5 采集审核工具、App Worker、进度事件和产物鉴权。项目与审核归属在服务端维护；任务排队、设备管理、批次和版本是执行细节，默认不放到普通用户的主界面。

阶段与载体仍分别记录，H5 规则不能未经确认直接用于 App。HTML 的 DOM 测量与手机截图的尺度校准保留各自的证据要求。执行失败、规范违规和待确认继续分别记录。

优先落地：项目归属与记录流 → 接入真实上线前审核 → 接入同项目手机走查与基线对比。每一步都提供可用的单独能力。

## Demo 的边界和体验路径

入口：`http://localhost:6173/lifecycle-demo.html`。沿用 React、Vite 和 CSS Modules，无新依赖。

- 点击 HTML 示例，依次体验修改稿复查、补充证据、确认本轮审核。
- 在结果下点击“检查上线效果”，看到同一项目的手机走查和基线引用；点击“查看依据”返回上线前结果。
- 点击左侧“11.11 官方会场”，直接查看一份已有前后关联的演示项目。
- 新建项目走查后，新的结果归入独立项目；下载 JSON 可检查项目 ID 与基线结果 ID。
- 支持文本输入、文件选择、拖放和粘贴图片；只在本地保存文件名与类型，**没有读取链接、上传文件或分析内容**，所示结果均为明确标注的模拟结果。刷新后重置。

正式产品要将会话、项目、文件、任务、基线和审核确认持久化，并由后端校验权限与证据。不能用当前浏览器内存状态代替正式门禁。

## 视觉与交互约定

白色主区 `#ffffff`、浅灰侧栏 `#f5f5f5`、文字 `#252525`。字体采用系统拉丁与 PingFang SC，正文 14px、中文行高 1.8。输入框圆角 24px，操作按钮 10px，消息气泡 22px。绿色只用于已复核状态，问题不铺大面积警示色。

主体阅读宽度 760px，侧栏 258px；760px 以下侧栏收起为可打开的项目列表。无看板、统计卡片、阶段导航或页面入场动画。常用操作立即更新，键盘可提交与换行，结果依据原地展开。

验证记录：TypeScript 与 Vite 构建通过。Ego Lite 验证四轮结果归属同一项目、手机结果引用已确认的上线前结果、原始问题与待确认项不被改写、跨项目记录隔离、基线跳转、项目搜索、缺材料提示、文件添加/移除与 JSON 导出。1440px、375px 与 320px 布局均无页面横向溢出。
