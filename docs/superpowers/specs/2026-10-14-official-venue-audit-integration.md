# 官方会场规范审核接入项目的开发方案

日期：2026-10-14  
状态：开发方案草案，运行链路尚未实施  
首版交付：历史会场证据复核

## 1. 交付目标

用户在项目界面选择已采集的会场和已经确认的规范版本，启动任务后，由项目完成模型识别、规则判定、像素测量、证据标注和报告生成。用户能查看逐会场进度、执行异常和失败项重试，无需 Codex 逐步执行命令或补救。

首版处理已有的两屏截图及配套历史测量记录。报告明确标记“历史证据复核”，展示证据采集时间和本次分析时间。这次复核不能证明实时页面仍符合规范，也不能替代 AutoGLM 安卓导航验收。

这是一项中等复杂度的前后端集成工作，预计涉及十余个文件。现成的识别、测量和报告工具可以复用，主要工作集中在数据契约、任务生命周期、规范快照和结果适配。沿用 FastAPI、PostgreSQL、Python 和 React。

## 2. 当前基础与缺口

| 已有基础 | 本次需要补齐的能力 |
| --- | --- |
| 规范巡查 Skill、规范原文和运行版本快照 | 保存并校验官方会场完整规则配置，包括激活状态、条件、阈值和例外 |
| Task、TaskRun、任务队列、重试和进度事件 | 增加不依赖手机的官方会场复核执行分支 |
| 截图模型分析、结构化事实和调用追踪 | 将会场两屏作为一个审核单元，接入现有任务执行 |
| 像素测量、H5 DOM 记录复核 | 将测量来源、有效性和判定结果保存到运行产物 |
| 搜索、统计、局部证据和框选报告 | 在项目任务结果页展示同一份会场结果数据 |
| 离线完整性校验和静态报告发布 | 增加支持部分失败的在线结果校验，提供经过鉴权的结果和资源访问 |

已保存的全量基线包含408个会场、816张原始截图。第5版配置保留23项规则，其中13项激活、10项未激活。审核、测量及证据展示工具的部分源码仍未纳入 Git 跟踪；发布到 gh-pages 的报告与主应用源码是不同交付物。

当前 `task_runner.py` 的普通分支会启动手机采集流程；新增任务模式必须有明确分支。现有图片采集监听器会扫描图片并触发逐图分析、OSS上传，不能直接用它监听会场复核目录，否则可能出现重复模型调用和错误的分析方式。

## 3. 首版范围

### 3.1 必须交付

1. 在现有任务管理页面创建“官方会场历史复核”任务，选择预登记证据包、会场记录及规范 Skill。
2. 创建运行时固化完整规范、选中会场、原图和配套测量的哈希，以及已确认人工修订的来源。
3. 将每个会场的两张原图共同输入审核服务，执行本轮激活规则；不依赖实时浏览器或 USB 手机。
4. 保留名称、会场ID、通天塔项目ID、来源页和行、采集时间及原始证据对应关系。名称与画面标题不同不自动判为异常。
5. 保存逐项观察、依据、测量值、结论和局部证据；界面展示疑似问题与待确认项。
6. 保存逐会场进度和检查点；重试时在新运行中复用有效的已完成结果，只补跑执行失败的会场。
7. 生成在线结果、JSON、CSV和可下载的HTML资源包；图像及DOM文件可以追溯到原始哈希。
8. 完成10个代表性会场的独立运行验收，再扩展到408个历史会场。

### 3.2 后续阶段

实时H5登录、后台表格翻页、二维码解码、两屏采集及DOM测量接入相同任务流程，作为下一次独立交付。PDF/Word自动拆解新规范、多人共享人工标注、安卓导航优化和多手机调度另行安排。

本轮生成的任务结果沿用项目访问权限。公开报告继续通过已有静态发布流程单独发布，任务完成不会自动把新结果推送到 GitHub Pages。

## 4. 实现结构

复用现有任务队列与运行记录，增加一个会场审核服务模块和一个任务脚本入口。原命令行复核工具与项目任务入口调用同一套审核逻辑，保留原CLI用法。

```text
管理员预登记历史证据包 + 已确认的规范 Skill
                       |
项目任务界面 --> Task / TaskRun / 原有任务队列
                       |
             官方会场复核执行分支
                       |
       模型识别 --> 规则判定与证据测量
                       |
        每会场检查点 + 运行汇总 + 报告产物
                       |
             项目结果页与鉴权下载
```

执行采用现有子进程方式，逐会场结果通过原子写入保存到运行目录，后台监听进度与进程结束并更新 TaskRun。SSE用于及时通知，运行目录中的检查点是刷新页面和恢复查询的依据，不能只依赖内存事件。

首版沿用现有队列互斥规则，不改变全局并发调度。会场复核不分配或占用ADB设备，但可能因已有任务占用队列而等待。部署保持单一调度实例。

会场审核分支使用独立的进度与完成处理，不触发普通截图采集监听器的OSS上传、通用逐图分析或向量入库。新增模式不得回落到手机采集的默认分支。

## 5. 输入和规范契约

### 5.1 历史证据包

首版由管理员预登记一个受控历史证据包，通过固定 `source_id` 选择。API不接收用户指定的本地路径，也不通过目录遍历公开其他采集资料。源包保持只读，运行目录仅复制选中的证据及必要规范资料。

每个会场必须有稳定的 `record_id`、名称、会场ID和项目ID，以及两张原图的文件名、尺寸、SHA256、采集时间和滚动位置。首屏由采集元数据确认，不能将滚动后的第二屏视作首屏。

DOM和实时截图是可选配套证据，保存其测量时间、文件哈希、会场身份、视口尺寸及尺度。未提供可靠的配套测量时，OV-009保持待确认。配套证据存在但哈希或会场身份不匹配时，记录证据完整性错误，不能用于判定。

已有人工修订仅在原图、规则和适用范围一致时复用，记录来源和哈希。模型回复中的未激活规则、未知规则、重复ID、越界坐标或错误数量不能被直接写成有效结论。

### 5.2 规范保存

复用 `AnalysisSkill` 及运行时 `analysis_skills_snapshot_json`。拟为 Skill 增加可空的 `audit_profile_json`，保存完整官方会场配置；原 `specification_json` 继续保存公共规范原文、版本和检查项。

两份定义需要校验标题、版本、规则ID及判据的一致性。快照同时保存完整配置和SHA256。官方会场配置不能直接塞入目前严格校验的公共 `Specification` 对象，也不能只复制激活规则而丢掉10项未激活记录。

带官方会场执行配置的 Skill 在首版只能绑定对应任务模式，避免普通逐图分析忽略它的激活状态和测量要求；既有普通规范巡查功能保持兼容。

本轮沿用 `5-h5-user-policy-2026-10-11`，关键判据保持如下：

- OV-009：只测分类Tab顶部与最近上方业务模块底部，7至9px含边界符合；灰色示意楼层及已确认家具例外跳过。历史DOM测量须经过组件语义、身份、哈希和尺度校验，不能通过截图近似框猜测精确间距。
- OV-010：feeds容器背景为 `#FFFFFF`，卡内白底不替代容器背景；语义不清的取样不能支持数值合规判定。
- OV-017：只统计主标题，上限8个字符；家具会场已经确认的四组主标题口径保留。
- OV-005与OV-023：共享首屏完整feeds商品证据，强制问题不重复计数。
- 其他判据、条件和未激活项直接沿用完整第5版配置，不重新解释或删除。

首次复核调用项目配置的视觉接口，保存实际请求及返回的模型标识。重建已有报告不能被记录为一次新的模型审核。

## 6. 拟新增接口和字段

以下为拟实施契约，不表示接口已经存在。

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/official-venue-sources` | 列出首版允许使用的预登记证据包及可选会场，隐藏服务器路径 |
| `POST /api/admin/tasks/official-venue-audit` | 创建复核任务，输入source_id、record_ids、analysis_skill_id；仅operator/admin可创建 |
| 已有任务run、retry、runs、progress及events接口 | 启动、失败项重试、查询历史、进度和事件；沿用现有权限 |
| `GET /api/admin/task-runs/{run_id}/venue-audit` | 返回指定运行的概况和会场结果；支持skip、limit及名称/ID/项目ID搜索，默认每页20个 |
| `GET /api/admin/task-runs/{run_id}/venue-audit/artifacts/{path}` | 下载原图、DOM或导出包；先检查运行访问权限，再校验资源路径及产物清单 |

拟增加任务模式 `official_venue_audit`。创建与启动均校验模式、证据包、选中ID和规范绑定，设备参数对该模式无效并应拒绝。只允许绑定一个官方会场规范Skill，避免同一次运行出现两套冲突判据。

拟增加两个可空JSONB字段：`AnalysisSkill.audit_profile_json` 与 `Task.audit_config_json`。任务配置保存输入包ID、选中record_ids和配置格式版本。TaskRun.result_json只保存运行概况、汇总计数及产物索引；完整会场结果和检查点保存在所属运行目录，以免任务列表和历史接口加载全量报告。会场ID映射和产物路径由索引维护，不新增独立会场数据库或任务服务。

数据库变更采用兼容性追加，旧行保持空值，旧客户端请求可以继续使用。修改Skill时递增版本，运行中的快照不变；重试默认沿用原运行的规范快照，选择新规范必须启动一次新的完整审核。

新会场报告从本次输入、规范和结果直接构建，不强制依赖旧 `results.json` 才能完成。历史对比是可选信息；模型识别不能把上一轮 `audit.json` 当成本轮新观察。

## 7. 状态、重试与恢复

### 7.1 执行状态与规范结论

TaskRun继续使用项目已有的排队、运行、完成和失败状态。每个会场另存执行状态与错误阶段，规则结论仍是 `pass`、`fail`、`uncertain`、`not_applicable`；未激活规则保留 `disabled`。

| 情况 | 执行及展示要求 |
| --- | --- |
| 有明确规范违规 | 审核执行可以完成，规范结论为fail；不因违规本身触发执行重试 |
| 页面已知未就绪 | 保留原始页面状态，激活检查为uncertain；汇总显示截图未就绪，不伪造通过 |
| 缺少可判定的组件边界 | 已执行的该项为uncertain，保留测量或候选位置与原因 |
| 模型超时、回复格式错误或必需原图损坏 | 会场执行失败；无有效检查结果的激活项使用明确的错误占位，不能当作正常完成 |
| 一部分会场执行失败 | 批次标记失败，同时保留已完成结果和部分报告；报告单列执行失败，不能继续显示为审核处理中 |
| 所有会场均完整处理 | 批次完成；报告仍可能包含违规、待确认及截图未就绪，完成不等于全部合规 |

顶部始终按会场统计，并显示选中数、执行完成数、执行失败数和证据覆盖情况。审核分类按单会场互斥计数；新增“审核执行失败”类别，避免混入规范疑似问题。检查项计数另列在详情，不作为会场总数。

### 7.2 重试与中断

重试创建新的TaskRun，并沿用现有 `TASK_MAX_RETRIES` 限制。已完成会场在输入截图、配套测量、规范、人工修订、审核实现及模型请求配置指纹相符时可复用，写明 `reused_from_run_id`；其余会场重新执行。

每个运行拥有独立输出目录和进程执行锁，同一运行不能同时执行两次。进程正常退出后仍须通过结果完整性校验才能完成。非零退出、产物不完整或未处理的会场必须形成明确失败原因。

后台重启后，先检查执行锁、进程和终态产物，恢复可以核验的终态；仍有执行进程时不得并行重试。无法确认继续执行的运行标记中断，并允许新运行从有效检查点恢复。不能仅凭历史PID终止进程，不能覆盖原始输入或旧运行结果。

## 8. 结果、证据和框选

每个会场保留名称、会场ID、项目ID、两屏信息、执行状态、23项检查记录、结构化事实、测量记录、调用追踪及 `check_evidence` 展示数据。

原图不因缩略图裁切而改变。框坐标保留原图像素单位，并与文件SHA256绑定。OV-009引用其实际配套截图，不能把实时DOM边界画到另一张历史首屏图上。整屏证据和缺少坐标的项目提供参考图与“暂无局部定位”提示。

结果页复用已有任务历史和查询入口，增加官方会场报告视图，保留浅红/浅绿状态背景、疑似与待确认项、规则激活状态、搜索和分页。运行结果JSON由后端提供；前端不重新计算规范判据。

支持适应宽度、2倍/3倍、审核框显示切换、人工框选、撤销及JSON导出。首版人工框选沿用本浏览器存储方式，不承诺跨浏览器共享，也不直接改变审核结论。图片加载失败时隐藏标注并提示重新查看。

在线JSON、图片和DOM下载全部检查TaskRun访问权限。前端通过鉴权请求加载资源，不在链接中暴露登录令牌。资源路径必须位于该运行的产物目录内并登记在清单中；拒绝越界路径、外部文件和不安全符号链接。

## 9. 开发顺序与改动范围

### 9.1 先建立可复现源码基线

整理已有审核、测量、身份校验、报告与框选源码，补齐依赖清单和使用说明；在隔离环境验证后单独提交。原始任务数据继续作为运行资料管理，历史报告和文件哈希保持不变。

这一步便于其他开发者复现工具，不视为项目自主巡查功能已交付。

### 9.2 完成历史会场复核版本

| 工作包 | 主要落点 | 交付结果 |
| --- | --- | --- |
| 输入及规范适配 | models、schemas、crud、database、analysis_skills、inspection | 可绑定完整第5版规范并保存运行快照，旧规范任务兼容 |
| 审核服务与CLI共用 | 新的 `backend/app/services/venue_audit.py`、现有 `rerun_venue_audit.py` 及报告工具 | 相同算法可被项目任务与CLI调用，原CLI结果口径保持一致 |
| 执行分支与进度 | task_queue、task_runner、task_events、admin路由及任务脚本 | 无设备的后台任务、逐会场检查点、终态校验和失败项重试 |
| 结果界面与资源 | frontend api、AdminTasks、AdminTaskResults、SkillEditor及证据组件 | 从界面选择会场、运行、查看规范快照、测量和框选报告 |
| 校验与部署资料 | backend/tests、现有报告校验工具、部署说明 | 隔离回归、10例验收及运行目录部署验证 |

新任务分支与API入口在审核服务和校验准备好后开放。迁移和公共规范字段改动单独保持向后兼容；功能发布必须同时包含后端执行、前端查看、输入证据部署及测试，不能只上线一个无法运行的入口。

### 9.3 后续接入实时H5

复用已验证的Ego Lite采集脚本，通过项目执行器创建并管理浏览器任务空间。处理登录需要的人工操作，完成后台分页、会场ID提取、两屏采集及DOM测量后，输入本轮审核服务。登录、采集与审核失败分阶段记录；不能把旧截图作为采集失败时未注明的替代证据。

这个阶段实施前，必须单独验证部署环境能访问用户授权的浏览器会话。成功调用审核模型不等于后台登录态或采集能力可用。

## 10. 验收与回归

### 10.1 首版业务验收

使用已固定的10例会场作为基础集，保留其输入哈希，并补充错误注入测试。固定集位于 `docs/examples/official-venue-pilot10-v3.json`；具体预期从人工确认的第5版记录形成验收清单。

1. 在项目界面选择10例、绑定第5版规范并点击运行，之后不通过Codex调用脚本或补改数据。
2. 正常处理时对应20张原图、230条检查记录，其中130条激活、100条未激活；未激活项不计入问题数，也不在会场明细展开。
3. 覆盖间距7/8/9px边界与超界、灰色示意跳过、家具例外、白色/非白色容器、标题超限、人物数量和首屏商品要求。
4. OV-009缺少有效DOM或语义边界时保持待确认；不能用近似模型框生成精确数值通过。
5. 覆盖页面未就绪、模型超时、非法回复、原图损坏、DOM身份错配及缺失资源；状态和失败原因与实际阶段一致。
6. 改规范或取消规则激活后，已有运行不变，新运行使用新快照；失败项重试不重新消耗有效已完成会场的模型调用。
7. 刷新页面、断开进度连接及中断执行后，能够查询持久化进度并正确恢复或重试。
8. 报告保留会场映射、真实模型标识、证据来源和框坐标；违规、待确认和执行失败能分别看到。
9. 在桌面和手机窄屏验证放大、框选坐标、撤销、导出及加载失败提示；跨用户访问产物按项目权限处理。

模型返回可能存在波动。自动化回归使用固定回复与测量夹具；真实接口验收检查关键判据、有效证据和失败行为，不要求每次模型自由文案逐字相同，也不把待确认强行改成通过。

### 10.2 技术回归

- 运行新增单元测试、数据库/API集成测试和前端构建；在干净工作区复现，避免未提交文件掩盖依赖缺失。
- 验证原有规范巡查、普通截图分析、安卓任务和Worker派发不受新增模式及字段影响。
- 确认新模式不会启动ADB、分配手机、触发普通采集监听或重复调用模型。
- 在线校验器检查选中会场覆盖、规则覆盖、输入身份、资源哈希及状态统计；支持明确部分失败，不能机械套用当前离线“全部成功”的打包断言。
- 10例验收通过后运行408例历史批次，检查816张原图对应关系和有限并发下的资源使用；全量处理完成不代表全部符合规范。

## 11. 依赖、风险与回退

| 依赖或风险 | 本轮处理 |
| --- | --- |
| PostgreSQL及项目鉴权 | 复用现有配置；迁移与测试使用隔离数据库 |
| 视觉API账户与额度 | 复用现有模型配置，不把密钥写入输入包或日志；实施时先以一例验证当日可用性，历史调用记录不作为当前连通证明 |
| 历史证据只存在开发机 | 管理员将只读证据包部署到后端可访问目录并登记；缺失时提示无法创建可执行任务 |
| 规范配置与公共Schema不同 | 使用明确适配及独立可空字段；禁止悄悄丢弃激活状态、例外或测量要求 |
| 组件语义或图像定位不清 | 输出待确认；已有人工修订须绑定证据与版本，不把局部取色结果扩展成整页结论 |
| 进程中断和旧缓存误用 | 独立目录、执行锁、原子检查点、指纹校验与新TaskRun重试 |
| 队列串行影响其他任务 | 沿用现状并在验收中观察等待时间，本轮不扩展并发调度 |
| 完整报告首屏加载较慢 | 先获取运行概况，按需加载会场及图片；延续分页和图片懒加载，下载完整JSON与资源包单独提供 |
| 程序发布不含依赖模块 | 校验部署包包含新增审核服务、脚本、报告JS/CSS及受控输入资料 |

首版的审核运行不需要Ego Lite登录会话、GitHub访问令牌、手机控制模型或新增OSS上传凭据。源码提交使用现有仓库授权，与用户执行审核任务分开；实时采集与公开报告发布分别验证其授权和依赖。

回退时停止新任务入口和新执行分支，保留旧运行、输入文件、规范快照及可空新增字段。先确认执行进程退出，避免新旧代码同时写同一目录。已有手机任务、规范分析和已发布静态报告继续使用原有路径，不通过删除业务数据回滚。

## 12. 实施前确认与完成定义

开发人员在开始集成时核验三个条件：历史证据包可访问且哈希有效；现有视觉接口能完成一次受控调用；现有任务进程结束与队列释放路径可被复用。浏览器登录与实时采集不作为首版启动条件。

本轮完成必须同时具备：已审查并提交的源码、已部署的输入包、通过的10例独立运行验收、前后端回归记录、可追溯的项目任务结果及使用说明。文档或静态报告单独更新不满足自主运行交付。
