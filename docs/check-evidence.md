# 检查项截图与框选

会场审核报告在每个激活检查项下提供“细节截图与框选”。疑似问题与待确认项直接展示在会场卡片中，其他检查可在“全部激活检查”内查看。

有局部证据时，报告围绕已有坐标展示细节截图，并叠加检查区域。红框对应疑似问题，黄色框对应待确认区域，绿色框对应通过项。只有整屏证据或缺少证据时，提供折叠的参考截图并明确显示“暂无局部定位”，不会根据文字描述推测或虚构位置。

OV-009 使用匹配的实时 H5 截图与 DOM 测量坐标。蓝线表示上方模块底部，绿虚线表示分类 Tab 顶部；零间距时两条线位于同一位置。业务模块身份未确认时，标注为候选边界。OV-010 的框保持实际像素取样尺寸，周围裁切仅用于帮助理解所在区域。

点击截图或“放大 / 框选”打开原图，可选择适应宽度、2倍或3倍显示，开启“新增框选”后拖动截图。人工标注为紫色虚线，支持撤销，可与自动审核标注区分。关闭查看器会保留原来的筛选、翻页深度与检查项展开状态。

人工框选自动保存在当前浏览器，可通过报告顶部“导出人工标注”下载 JSON。分享链接包含生成报告时的自动审核标注，个人后补框选不会同步给其他浏览器。导出记录包含会场 ID、项目 ID、规则 ID、原图文件、原图 SHA256 和原图像素坐标，可用于人工交接；人工标注不直接修改审核结论。

## 生成与验证

使用原有报告构建入口即可生成细节证据：

```sh
python scripts/build_venue_recheck_report.py --output <报告目录>
python scripts/validate_venue_reaudit.py --output <报告目录>
PYTHONPATH=backend python -m unittest backend.tests.test_venue_check_evidence
```

报告目录需要一同发布 `report.html`、`check-evidence.js`、`check-evidence.css` 和报告引用的原始截图、实时截图及测量记录。发布入口 `index.html` 应与 `report.html` 同步更新。

构建器核验截图哈希和尺寸，保持框坐标不变，仅扩展周围显示范围。实时测量同时核验 DOM 哈希、会场身份、截图尺度与边界间距。新增的 `check_evidence` 为报告展示数据，原有 `audit.checks`、规则结论和原图保持原状。
