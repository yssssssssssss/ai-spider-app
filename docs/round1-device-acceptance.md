# 第一轮安卓真机验收

日期：2026-10-09。代码版本：`7e38cc36bb4690777894eb08e968736300088dfe`。

结论：新品专用巡查、规范分析、证据、版本与导出链路通过；通用 AutoGLM 导航未通过验收，需要改进目标停止条件和完成状态校验。

## 环境与范围

- OnePlus 7T HD1900，Android 12，1080×2400；京东 15.10.50。
- 手机经 USB/ADB 接入，使用项目真实 Worker、FastAPI、视觉接口与前端。
- 使用独立 PostgreSQL/pgvector 数据库和本地验收服务，未使用业务数据库进行测试。Worker 上传至本地后端并保存截图；本次关闭云端 OSS 上传，没有验收云端存储。
- 规范仍为项目现有 3.7 条款抽取的双入口排列试用规则，尚未由业务规范负责人校准。

专用报告给出 8 项通过、3 项不符合、2 项不适用。三个不符合项涉及三入口组件内容、第二个 Tab 的文字颜色以及横滑时区域外稳定性。原图核对发现区域外存在搜索词和商品轮播变化；最后一项不能直接归因为横滑操作，应由业务复核。这里记录的是现有规则的输出，不能代替正式业务验收。

新品专用任务沿用专用报告流程，绑定的试用规范本次通过截图分析接口主动执行。通用任务上传截图后自动执行绑定规范；未把两种运行方式混为一谈。

## AutoGLM 的三次试验

1. 从手机桌面开始，第一次流式请求收到模型服务的内容过滤错误。任务正确失败、未生成最终截图，设备释放正常。
2. 从已打开的京东首页开始，模型成功点击到新奇集市，但继续滑动。30 次模型调用后触达步数上限，任务正确失败；采集并上传了 20 张过程截图。对应截图分析有 18 项成功、1 项失败、1 项跳过；另加单独的首页反例后，跳过合计 2 项。失败项为模型返回空内容，严格结果校验阻止了无效规范结论。
3. 明确写入停止条件并包含 `finish(...)` 示例后，模型回复包含结束指令和尚待执行的点击说明，被导航 SDK 解析为完成。实际保存的仍是京东首页。平台任务标记为 `completed`，截图分析正确跳过，目标覆盖显示 `uncertain`。本次不能认定为成功到达。

这三次试验确认了入口能够返回并执行 AutoGLM 动作，同时说明仅凭 SDK 的完成信号不能证明目标页已到达。后续应在完成前验证最终截图，并使目标页否定结果影响任务完成状态；停止条件应由执行器约束。单纯调整提示词还不足以通过验收。

## 模型和可复核产物

- 视觉接口：请求 `GPT-5.5`，返回 `gpt-5.5-2026-04-24`，主机 `modelservice.jdcloud.com`。
- 手机导航：请求及返回均为 `ZhipuAI/AutoGLM-Phone-9B`，主机 `api-inference.modelscope.cn`，32 次流式调用，其中首次失败。
- 接口返回名称是服务报告的标识，不独立证明其内部模型权重。

本机生成目录：`data/tasks/round1-device-validation/`，不纳入 Git。包含：

- `acceptance-summary.json`：运行状态、耗时、规范结果及实际模型记录。
- `floor-report.json`、`floor-report.xlsx`、`floor-report.zip`：新品任务完整导出。
- `autoglm-report.json`、`explicit-report.json`：通用导航失败及错误完成的复现数据。

前端 TypeScript/Vite 构建通过；Ego Lite 实测结果展示、证据区域、历史切换及 JSON 导出按钮，并下载 Excel、ZIP 后回读验证完整内容。验收没有改动业务代码，也未部署远端。真实 USB 拔插、锁屏恢复、跨业务频道及正式规范准确率尚未验证。
